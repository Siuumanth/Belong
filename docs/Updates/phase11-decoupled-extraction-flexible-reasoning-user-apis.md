## 1. Overview & Architectural Goals

Phase 11 delivers four major core architecture improvements to Belong:
1. **Decoupling extraction from question IDs** using a central schema taxonomy (`PROFILE_DIMENSIONS`).
2. **Adding an emergent signal escape hatch (`other_signals`)** so novel user insights are captured without forcing them into wrong categories.
3. **Preserving raw onboarding dialogue** alongside structured signals in profile JSON and incorporating them into vector embeddings (`CanonicalSerializer`).
4. **Loosening Stage 2 LLM matching reasoning** into open-ended, evidence-grounded analysis written directly **to the user in second-person voice ("You")**, supported by exposed REST APIs and complete OpenAPI documentation.

## 2. Detailed Technical Changes

### 1. Decoupled Signal Extraction & Schema Taxonomy
- **Centralized Schema (`schema_config.py`)**: Created `PROFILE_DIMENSIONS` defining core profile structure (`self`, `wants`, `constraints`).
- **Decoupled Prompt (`prompts.py`)**: Updated `SIGNAL_EXTRACTION_PROMPT` to inspect the complete answer and extract whatever standard dimensions or novel insights it contains.
- **Escape Hatch (`other_signals`)**: Added support for extracting and storing `other_signals` / `novel_signals` in `belong-api/onboarding/graph.py`.

### 2. Raw Dialogue Preservation & Hybrid Vector Embeddings
- **Raw Dialogue Persistence**: `finalize_profile` in `belong-api/onboarding/graph.py` fetches the user's original onboarding messages from `conversation_messages` and attaches `raw_responses` and `raw_dialogue` into `profile_json`.
- **Hybrid Embeddings (`serializer.py`)**: `CanonicalSerializer` serializes structured signals, `Other signals`, and compact `Raw dialogue` into the canonical text representation converted into vector embeddings.

### 3. Second-Person User-Facing Voice in Matching LLM Reasoning
- Updated `PAIRWISE_REASONING_PROMPT_TEMPLATE` in `belong-workers/config.py` and `belong-api/config.py`.
- Instructed the LLM reasoner to address User A directly as **"You"** and refer to User B by their name (e.g. "Alex") or "they".
- **Voice transformation**:
  - *Old*: `"User A wants quiet support and User B provides calm listening."`
  - *New*: `"You seek quiet emotional support during stress, which Alex naturally provides through steady, calm listening."`
- Kept exact signal ID citations (`evidence_a_ids`, `evidence_b_ids`) for strict factual grounding.

### 4. Exposed REST APIs & OpenAPI Specifications
Updated `belong-api/api/routes/matches.py` and `belong-api/matching/schemas.py` to expose three REST GET endpoints:

| Endpoint | Method | Description |
| :--- | :--- | :--- |
| `GET /matches/{user_id}` | `GET` | Retrieves all latest qualitative compatibility match candidate breakdowns for `user_id` (joins candidate names from `profiles`). |
| `GET /matches/jobs/{job_id}/results` | `GET` | Retrieves all qualitative match candidate breakdowns generated by a specific matching job run (`job_id`). |
| `GET /matches/details/{result_id}` | `GET` | Retrieves full qualitative breakdown for a single compatibility match record (`result_id`). |

Pydantic schemas (`MatchCandidateResponse`, `MatchesListResponse`) were updated with OpenAPI descriptions and fields (`id`, `match_id`, `user_a_id`, `user_b_id`, `user_b_name`, `overall_verdict`, `overall_reasoning`, `dimension_results`, `complementary_alignments`, `shared_alignments`, `potential_conflicts`, `dealbreaker_violations`, `uncertainties`, `created_at`, `updated_at`).
